# Agent 开发指导

本工作区内的 Agent 开发工作必须遵循以下约定。原始约定保留在同级 `SKILL.md`；
当两者存在歧义时，以用户的当次指令为准。

## 分支工作流

- 所有开发均在功能分支进行，不直接向 `main` 提交。
- 分支上可随时提交，以保存可用、未完成或实验性的改动。
- 仅在用户已实际验证、暂定稳定且没有明显 bug 后，才可合并至 `main`。
- 合并至 `main` 时使用普通 merge，保留分支提交历史。

## Commit 消息

采用 MAA 风格：`<类型>(<可选作用域>): <中文主体>`。

- 类型前缀必须为小写英文：`feat`、`fix`、`docs`、`chore`、`style`、`refactor`、`test`、`perf`。
- 可选作用域使用英文，例如 `fix(server): ...`、`docs(readme): ...`。
- 主体使用中文描述；必要的技术名词可保留英文。

## 分支命名

- 使用英文短横线命名，并带类型前缀，例如 `feat/xxx`、`fix/xxx`、`docs/xxx`、`chore/xxx`。

## 推送策略

- 工作分支可定期推送到 `origin` 备份；个人工作分支可使用 force-push。
- 每次合并到 `main` 后推送 `main`。
- 强制推送远端或改写历史前，必须先征得用户确认。

## 稳定性判定

- “暂定稳定”指用户已亲自完成该项目的关键使用流程，且未发现明显 bug。
- 未满足该条件时，不得自行合并至 `main`。
